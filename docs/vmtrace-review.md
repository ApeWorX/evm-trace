# vmTrace compatibility investigation

Investigated September 13–14, 2026, against evm-trace upstream `72e892bf5` (the latest `main` fetched from ApeWorX). The unchanged baseline passed its 35 tests, but had no vmTrace tests. This change adds offline regression coverage and retains the live responses used below.

## Client support and evidence

Supporting `trace_transaction` does not establish support for compressed opcode traces. The relevant request is an ad-hoc `trace_*` method with `"vmTrace"` in its trace types.

| Implementation | Compressed vmTrace                           | Evidence and qualifications                                                                                                                                                                                                                                                                                                                                                               |
| -------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reth           | Yes                                          | Live Reth `v2.5.0-189c0df`, using `trace_call`, `trace_replayTransaction`, and `trace_replayBlockTransactions`. Serious output defects below.                                                                                                                                                                                                                                             |
| Erigon         | Yes                                          | [OeTracer source](https://github.com/erigontech/erigon/blob/b12585ee1c09cfe5753dc1ddb89d6a966de930ec/rpc/jsonrpc/trace_adhoc.go). Reviewed source, not a running Erigon node.                                                                                                                                                                                                             |
| Nethermind     | Yes                                          | [ParityLikeTxTracer](https://github.com/NethermindEth/nethermind/blob/084da7e9469da574851568d32d8405d6bd747e6b/src/Nethermind/Nethermind.Blockchain/Tracing/ParityStyle/ParityLikeTxTracer.cs). Reviewed source and tracer tests, not a running node.                                                                                                                                     |

Source-only findings; the repository's last push reported by GitHub was in May 2025.                                                            |

Parity/OpenEthereum is the historical format origin. Its `op` and `idx` fields are not required: Erigon adds them outside compatibility mode, Reth omits `idx`, and the reviewed Nethermind/Besu serializers omit both. evm-trace previously required both fields and therefore rejected their ordinary responses.

## Live Reth failures

The [saved synthetic responses](../tests/data/vmtrace/reth.json) contain the request, code/state overrides, block number/hash, client version, Parity VM and call traces, struct logs, and callTracer output. These are read-only simulations, not transactions broadcast to mainnet.

| Case                                    | Observed defect                                                                                                                                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mstore`, code `60016000525f00`         | MSTORE's delta is empty. The subsequent PUSH0 contains the **previous** memory snapshot with `off=32`, although the write was at offset zero. Replaying those deltas produces 64 bytes with the value in the wrong word.                                     |
| `call`, `create_return_code`            | Successful CALL and CREATE report `ex.push=[]`, omitting the success flag or created address. The resumed struct log has the result on its stack. The converter now reports an explicit missing-result error rather than failing later with stack underflow. |
| `storage`                               | SSTORE changes slot zero from 7 to 42, but every `ex.store` is null. Geth-style output records the changed value.                                                                                                                                            |
| `storage` and other straight-line cases | `ex.used` equals gas **before** the instruction, rather than the remaining gas after execution.                                                                                                                                                              |
| `create_success`, `consecutive_create`  | A child executing only STOP causes the entire root `vmTrace.ops` to be empty. Struct logs and callTracer retain successful CREATE operations.                                                                                                                |
| `underflow_call`, `underflow_add`       | Faulting instructions still contain non-null execution records; treating these as completed operations cannot reconstruct the stack correctly.                                                                                                               |

Block 1,000,000 exposed another live difference: for transaction `0xea1093d492a1dcb1bef708f771a99a96ff05dcab81ca76c31940300177fcf49f`, block replay returns `code="0x"` for the root and CALLCODE child, whereas individual replay includes both bytecodes. The operations and call traces agree. The running revision's [block replay path](https://github.com/paradigmxyz/reth/blob/189c0df/crates/rpc/rpc/src/trace.rs#L541) calls `into_trace_results`, while individual replay uses `into_trace_results_with_state`, which fills bytecode.

Current revm-inspectors `8865141c577b1ef4c9b86dd865619fd9e53564df` still has relevant source paths. [The Parity builder](https://github.com/paradigmxyz/revm-inspectors/blob/8865141c577b1ef4c9b86dd865619fd9e53564df/src/tracing/builder/parity.rs#L320) breaks out of the entire traversal for the STOP optimization. Its instruction builder emits `off=memory.len()` with a full memory snapshot, uses pre-step gas, and always constructs `Some(ex)`. [Step collection and call completion](https://github.com/paradigmxyz/revm-inspectors/blob/8865141c577b1ef4c9b86dd865619fd9e53564df/src/tracing/mod.rs#L397) explain the result-push timing: the parent snapshot is collected before call completion, without repairing the push on return. The [Parity configuration](https://github.com/paradigmxyz/revm-inspectors/blob/8865141c577b1ef4c9b86dd865619fd9e53564df/src/tracing/config.rs#L175) also omits state-diff recording for VM-only requests. These source observations support the live findings; they are not a live test of that newer revision.

Do not repair these by assuming empty pushes mean success, moving arbitrary deltas by one instruction, or silently declaring an empty root trace valid. Those heuristics lose failures, nested calls, terminal writes, or actual empty executions. A client fix and fresh differential fixtures are needed before advertising Reth VM-trace equivalence. The library's new missing-push check detects one defect, not every malformed client response.

## Erigon history and current gaps

The historical fixes are merged: [SMOD #4806](https://github.com/erigontech/erigon/pull/4806), [missing pushes #4808](https://github.com/erigontech/erigon/pull/4808), [PUSH0 #7970](https://github.com/erigontech/erigon/pull/7970), and [EXTCODECOPY #8108](https://github.com/erigontech/erigon/pull/8108). The reviewed source retains SMOD's push, covers PUSH0 through PUSH32, and reads EXTCODECOPY's offset/size from stack positions 1 and 3. These specific fixes have not disappeared from the inspected source.

However, Erigon's `OnOpcode` still excludes MCOPY from both its memory-range selection and its memory-delta emission switch. Besu's `generateTracingMemory` also excludes MCOPY even though its [MCopyOperation](https://github.com/besu-eth/besu/blob/78ef664153fb4cf88371751b6fb4bc39ad531d44/evm/src/main/java/org/hyperledger/besu/evm/operation/MCopyOperation.java) modifies memory. These are source-confirmed omissions, not live Erigon/Besu reproductions. The library can reconstruct MCOPY deterministically from the existing memory and three stack operands, so the patch does that even if no delta is supplied.

Nethermind's [DUP implementation](https://github.com/NethermindEth/nethermind/blob/084da7e9469da574851568d32d8405d6bd747e6b/src/Nethermind/Nethermind.Evm/EvmStack.cs#L2072) traces the existing operands before copying the duplicate. Its [DUP tracer test](https://github.com/NethermindEth/nethermind/blob/084da7e9469da574851568d32d8405d6bd747e6b/src/Nethermind/Nethermind.Evm.Test/Tracing/ParityLikeTxTracerTests.cs#L451) checks that prefix. Erigon/Besu/Reth also include the duplicate. Replaying DUP/SWAP directly avoids relying on this dialect difference. Nethermind also explicitly removes several faulting operations in `ReportOperationError`; a compressed trace that omits a frame cannot recover that frame from deltas alone.

## Library fixes and differential results

The fixes cover optional opcode/index fields, null VM traces, Cancun stack effects, memory growth caused by reads and call inputs, MCOPY, DUP/SWAP dialects, and execution-context addresses. Memory is now captured before expansion, consistent with [modern Geth's interpreter](https://github.com/ethereum/go-ethereum/blob/101035a1049c7dc468bfe973478b579d9883d7b6/core/vm/interpreter.go).

Call-tree fixes cover left-padding short address words, CALLCODE's type and arguments, calls without child opcode frames, consecutive CREATE lookahead, creation initcode/output, inherited DELEGATECALL value, execution errors, LOG0, zero-filled memory reads, Parity depth/optional metadata, and preserving the caller's input dictionaries.

- All 33 synthetic cases agree between reconstructed struct-log call trees and callTracer on type, address, depth, value, input, output, and failure status. Parity call trees also agree after accounting for its deliberately omitted zero-value precompile and its CREATE label for CREATE2.
- Four historical mainnet transactions at blocks 17,000,000 and 22,000,000 contribute 5,477 struct-log frames. Their call trees agree across all three representations. `trace_transaction` agrees with the call-trace portion of `trace_replayTransaction`.
- Blocks 1,000,000 (two transactions) and 1,000,001 (one transaction) agree with individual replay on output, call traces, and VM operations. The multi-transaction case exposed the missing-bytecode defect above, which is asserted separately rather than normalized away without notice. This is not an exhaustive test of inter-transaction state dependencies.
- Thirteen straight-line synthetic VM traces match struct-log pc/op/depth/stack fields. Memory/storage/gas are **not** included in that claim; the client defects above are separately asserted in the fixture tests.
- The unchanged upstream passes 35 original tests but fails 95 of the added regression cases. The patched suite passes 148 tests, including Python 3.10 with minimum supported py-evm 0.10.1b1. The fixtures also ran with Python 3.13 / py-evm 0.12.1b1.

This is a bounded investigation, not exhaustive client conformance testing. Only Reth and the installed Anvil binary were queried live. Gas totals differ between opcode and call tracers; precompile return data may be unrecoverable without return-data capture; synthetic VM frames still expose only per-call reported storage deltas and omit gas/refund/error fields. Missing client data cannot always be repaired by this library.

## Reproduction

From the repository root with the local archive endpoint at `http://127.0.0.1:8545`:

```sh
uv run --python 3.13 scripts/collect_trace_cases.py /tmp/reth-vmtrace.json
uv run --python 3.13 scripts/collect_mainnet_traces.py /tmp/mainnet-vmtrace.json.gz
uv run --group test pytest tests/test_trace_regressions.py
```

Collectors select a fixed block per experiment and preserve all compared responses. The historical fixture uses deterministic gzip solely to avoid committing megabytes of repeated memory snapshots. The Anvil probe used a disposable, unforked instance on port 19547 with chain ID 52345678; it was stopped after testing. Its [responses](../tests/data/vmtrace/anvil.json) are included as version-specific evidence.
